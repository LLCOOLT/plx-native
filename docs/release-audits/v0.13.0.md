# Release audit — v0.13.0

The evidence behind [the v0.13.0 release note](https://github.com/l-tata/plx-native/blob/main/docs/release-notes/v0.13.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

This release is cut from the fork `l-tata/plx-native`, not from `GLinnik21/plx-native`. It carries two pieces of work, landed on `main` as two squash commits: the desktop apps for macOS and Windows, and the television changes (Live TV sound, settings, tuning, 4K, artwork).

This audit's generated half covers the television package only.

## External compatibility reports known at release time

None for this version.

## Compatibility tiers, and what moved

Nothing moved on the television. The maintainer's watching is recorded above without a model or platform release, so it is not a new line in the tiers. No Starfish, ACB or FFmpeg binding changed. One libcurl change: the artwork workers perform their requests inside a per-thread `curl_multi` handle (`plx_net::net::pool`), binding the seven `curl_multi_*` symbols `media::curlio` already binds, in an optional table; reviewed by the firmware-compatibility check (all seven present on every release in the inventory, 1.2.0 to 11.2.0), and its findings (IPv6 resolve pins, a failed `curl_multi_wait`, a pin after an unpinned request, certificate-reading and key-pinned requests) fixed before release.

## Known issues at release, with provenance

- **High-bitrate 4K channels have under a second of cushion.** From the Load payload (`srcBufferLevelVideo` maximum 8 MB) and the bitrates; not measured on a set. The start no longer hangs on it (`engine::decoder_ready`'s full-lane escape, host-tested).
- **Styled subtitles are not drawn in the Windows app.** Documented in `docs/windows-app.md`.
- **The v0.12.0 note claimed a Live TV audio fix that did not hold.** Corrected in that note's `Updates to this note`; the cause was pre-keyframe audio fed at time 0 (`engine::feed_audio_lane`), fixed here with a hostsim regression test.

## Deliberately not done

- The video pipeline's 8 MB video source-buffer ceiling was not raised: no measurement of what this firmware accepts above it.
- The replay fixtures and documentation screenshots were not regenerated (as for v0.9.0 to v0.12.0).
- The webosbrew listing and the `webosbrew/apps-repo` submission belong to the upstream project and were not touched.

## Release configuration

| | |
|---|---|
| flavour | `com.beb.plxnative` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK unchanged, Rust nightly pinned by date in the `RUST_NIGHTLY` repository variable |

New in the release run: `desktop.yml`, called with the tag, builds the macOS and Windows apps and a later job attaches their zips to the published release; a desktop failure leaves the television release intact. The binary-size budget (`ci/build-budgets.json` `binary_bytes`) was raised to 13,400,000 by the owner's decision, after 0.12.0's virtual channels took the stripped ARM binary past the old limit. No new outbound host, payload file or file outside the app's own directory on the television. The fork's repository has no production telemetry variables, so this build compiles in no telemetry endpoint.
